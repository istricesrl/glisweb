il sistema di log
=================
I log si scrivono con logger() ( _src/_config.php ), o con logWrite() che le inoltra il messaggio, in
`var/log/<canale>.<livello>.<anno e mese>.log`: il livello è nel nome del file, quindi un evento finisce nel
file della sua gravità. Si scrivono solo i messaggi di livello minore o uguale a LOG_CURRENT_LEVEL, che viene
da `debug.<stage>.log.lvl` ( _src/_config/_020.debug.php ); i default sono in _src/_config/_000.debug.php:

stage | livello | cosa si scrive
------|---------|---------------
DEV   | LOG_DEBUG   | tutto
TEST  | LOG_NOTICE  | fino agli eventi significativi
PROD  | LOG_WARNING | guasti e anomalie gestite ( fino al 21/10/2026 era LOG_ERR )

Il livello si sceglie per la gravità vera dell'evento, non per farlo comparire in produzione: i file `*.err`
e `*.crit` sono quelli che guardano i controlli dei deploy, e un evento normale scritto lì nasconde i guasti.

livello     | quando
------------|-------
LOG_EMERG, LOG_ALERT | il deploy intero è inservibile
LOG_CRIT    | un componente essenziale è giù ( sessione, database, un'estensione PHP necessaria ) o i dati sono a rischio ( una mail inviata e non copiata in mail_sent )
LOG_ERR     | un'operazione che doveva riuscire è fallita: un guasto, una configurazione mancante che blocca una funzione, un dato perso
LOG_WARNING | un'anomalia gestita: un errore dell'utente ( password errata ), una richiesta respinta da una regola ( controller before, antispam, coupon ), un dato in ingresso sbagliato, una funzione opzionale non configurata
LOG_NOTICE  | un evento normale ma significativo ( un consenso, che il suo registro lo ha nel database, un logout, una patch applicata )
LOG_INFO    | il flusso normale ( una cache mancante e ricostruita, un file importato, un pagamento riuscito )
LOG_DEBUG   | tracce e dump

Un registro con valore legale non si tiene nei log: i consensi stanno in anagrafica_consensi,
carrelli_consensi e consensi_contatti, e il log privacy ne è solo la traccia.
