Guide pratiche passo passo alla creazione di file PDF.

> **nota** — questo capitolo riguarda i PDF che l'**applicazione** produce: documenti, etichette,
> report. Il PDF della **documentazione** — il manuale intero, quello che si scarica dalla barra
> laterale — non passa di qui: lo stampa chromium dalla pagina unica generata da
> `_src/_cli/_docs.build.php`, con il CSS di stampa delle pagine.

introduzione
============
Per la creazione di PDF il framework si appoggia alla libreria [...]. A livello di organizzazione del codice, i file PDF vengono generati in due
passaggi:

- un'API specifica che genera l'oggetto PDF vero e proprio
- un'API (o una funzione) di default che recupera i dati necessari a generare una certa classe di PDF (ad esempio i documenti)
- una funzione che, ricevendo in input l'oggetto PDF e i dati recuperati li unisce producendo il PDF finito

Questo doppio passaggio, che può sembrare macchinoso, consente però notevole flessibilità e in particolare permette di realizzare facilmente
alcuni risultati non banali, come ad esempio:

- la possibilità di accodare più documenti nello stesso PDF
- estrema facilità di customizzazione dell'aspetto dei documenti senza dover riscrivere le logiche

Riguardo alla macro di default, tipicamente ne viene creata una unica per ogni entità che dev'essere stampata (ad esempio _documento.default.php, _anagrafica.default.php, _contratto.default.php eccetera)
e similmente avremo una funzione specifica per il recupero dei dati dell'oggetto in questione (ad esempio generaContenutiDocumento(), generaContenutiAnagrafica() e così via);
in questo modo potremo creare diverse API di stampa specifiche per tipo di stampa e formato (ad esempio _scheda.cliente.pdf.php, _scheda.fornitore.pdf.php, _badge.collaboratore.png.php eccetera)
che faranno riferimento sempre alla stessa macro (_default.anagrafica.php) e alla stessa funzione di generazione dei contenuti.

Per i documenti il pattern è chiuso in una funzione sola, `generaDocumentoPdf( $id, $percorso, $etc )`
( `_mod/_0400.documenti/_src/_lib/_pdf.tools.add.php` ), che riceve l'id del documento e il percorso dove salvarlo e:

- recupera i dati con `generaContenutiDocumento()`
- sceglie il modello: `$etc['modello']` se c'è, altrimenti la colonna `stampa_pdf` della tipologia del documento,
  poi quella della tipologia genitore, poi `$etc['predefinito']`, infine `documento.generico`
- chiama la funzione di disegno del modello, il cui nome si ricava dal modello stesso ( `ddt` → `generaDdtPdf()`,
  `copertina.missione` → `generaCopertinaMissionePdf()` )
- salva il file e annota l'attività di stampa ( tipologia 23 ) con `registraStampaDocumento()`, a nome dell'account
  in sessione
- restituisce il percorso del file, oppure `false`

Le API di stampa dei documenti sono quindi sottili: includono la macro di default per l'autorizzazione e poi
`_documento.output.php`, che salva in `var/spool/docs/<cartella>/pdf/` e manda il file al browser:

```php
<?php

    // inclusione del framework
    require_once '../../../../../_src/_config.php';

    // configurazioni specifiche
    $cnf['estensione'] = 'pdf';
    $cnf['cartella'] = 'ddt';               // sottocartella di var/spool/docs/
    $cnf['predefinito'] = 'ddt';            // modello se la tipologia non ne dichiara uno
    $cnf['attivita'] = false;               // l'attività la annota generaDocumentoPdf()

    // inclusione dei dati base
    require DIR_BASE . '_mod/_0400.documenti/_src/_api/_print/_documento.default.php';

    // generazione, salvataggio e uscita
    require DIR_BASE . '_mod/_0400.documenti/_src/_api/_print/_documento.output.php';
```

Il file si salva sempre; i parametri della richiesta scelgono solo l'uscita: `d` lo manda come allegato, `f` restituisce
un JSON col percorso salvato, senza parametri ( o con `fi` ) lo mostra nel browser. `print/0400.documenti/documento.pdf`
stampa un documento di qualunque tipologia col suo modello, e accetta `n` per salvarlo in un percorso dato.

Per personalizzare la stampa di una tipologia in un deploy **non si copia l'API**: si scrive la funzione di disegno
custom ( p.es. `generaDdtMioClientePdf()` in `src/lib/pdf.tools.add.php` del modulo ) e si dichiara il modello
( `ddt.mio.cliente` ) in `tipologie_documenti.stampa_pdf`, oppure lo si forza con `$cnf['modello']` in un'API custom.
Per le stampe di altre entità ( anagrafiche, contratti ) lo schema resta quello a tre pezzi descritto sopra.
