Descrizione del meccanismo di invio degli SMS del framework.

introduzione
============

la coda degli SMS
=================
Gli SMS non partono nel momento in cui vengono chiesti: finiscono nella tabella `sms_out` e un task li spedisce uno
per giro, con lo stesso schema della coda delle mail. Quelli spediti passano nella tabella `sms_sent`. Le due tabelle
hanno le stesse colonne nello stesso ordine ( capitolo `315.database.s.md` ) e il modulo `SM000.sms` ne è
l'interfaccia di amministrazione.

accodamento degli SMS
---------------------
Si accoda con `queueSms()` o con `queueSmsFromTemplate()` di `/_src/_lib/_sms.tools.php`: il mittente viene salvato
serializzato nella forma `array( nome => numero )`, i destinatari come array di numeri, il corpo in chiaro; il
parametro `$server`, se c'è, sceglie uno dei server di `$cf['sms']['servers']`, altrimenti vale quello del profilo
corrente. I template di `queueSmsFromTemplate()` stanno in `$cf['sms']['tpl']`: il runlevel
`/_src/_config/_340.sms.php` ci mette quelli dichiarati nel codice e quelli del database ( `template.se_sms = 1` ), con
mittente, destinatario fisso e testo presi per ogni lingua dalla linguetta contenuti del template ( colonne
`mittente_nome`, `mittente_numero`, `destinatari_numero` e `testo` di `contenuti` ). Fino al 2026-09-30 i contenuti dal
database non venivano letti.

evasione della coda degli SMS
-----------------------------
La coda la evade il task `/_src/_api/_task/_sms.queue.send.php` ( `/task/sms.queue.send`, o la sua copia identica
`/task/SM000.sms/sms.queue.send` nel modulo ), di solito dal cron: marca una riga con il proprio token, la spedisce
con la funzione del provider scelta dal `type` del server e, se l'invio riesce, la sposta in `sms_sent`. Se l'invio
fallisce, o se il server non è configurato o è di un tipo che il task non conosce, l'SMS resta in coda, `tentativi`
sale di uno e l'invio viene rimandato di tante ore quanti sono i tentativi fatti, fino a
`$cf['sms']['tentativi_massimi']` tentativi falliti ( default 10, runlevel `/_src/_config/_540.sms.php`; 0 toglie il
limite ): lì l'SMS resta in `sms_out` fermo con il token dedicato `TROPPI_TENTATIVI`, con un errore nel log `sms` e il
titolo della scheda che lo dice, e non lo riprendono né il cron né "elabora coda" ( `full=1` ); lo fa ripartire, con i
tentativi azzerati, l'invio forzato dalla scheda dell'SMS in uscita. Con il
token il task scrive l'ora della marcatura in `timestamp_elaborazione`, e all'inizio di ogni giro sblocca le righe
marcate da più di `$cf['sms']['minuti_sblocco']` minuti ( default 60, runlevel `/_src/_config/_540.sms.php` ),
tranne quelle bloccate apposta col token `COPIA_FALLITA` dopo un invio riuscito e una copia fallita e quelle ferme
per troppi tentativi. Le
modalità ( `id`, `hard`, `full` ) sono descritte con il task nel capitolo `212.file.api.md`. Le code si svuotano con
`/task/sms.queue.clean.out` e `/task/sms.queue.clean.sent` ( o le copie nel modulo ).

provider di invio
=================

Il provider lo sceglie il `type` del server in `$cf['sms']['servers']` ( runlevel `/_src/_config/_540.sms.php` e
`/_src/_config/_545.sms.php` ); il task legge del server `username` e `password`, e per Ehiweb anche `id_api`.

Le funzioni dei provider portano ogni destinatario in formato internazionale con `string2smsNumber()` di
`/_src/_lib/_sms.tools.php`, quindi in coda i numeri si possono scrivere come capita: un numero che comincia con `+` o
con `00` è già internazionale ( `0044 20 ...` diventa `+4420...` ), uno che tolti spazi e segni è `39` seguito da 10
cifre ha già il prefisso italiano, tutti gli altri sono numeri italiani e ricevono `+39` ( `333 1234567` e
`06 1234567` diventano `+393331234567` e `+39061234567` ). Skebby riceve il numero con il `+`, Ehiweb senza. Fino al
2026-09-30 ogni provider faceva la sua pulizia, e Skebby trasformava `+39 333 ...` in `+39393...`.

invio tramite Skebby
--------------------
Server con `type: skebby`, inviato con `skebbySend()` di `/_src/_lib/_skebby.tools.php`.

invio tramite Ehiweb
--------------------
Server con `type: ehiweb`, inviato con `ehiwebSend()` di `/_src/_lib/_ehiweb.tools.php`.
