le tabelle del database di supporto SA - SZ
===========================================

sconti
------
Questa tabella *gestita* contiene gli sconti, percentuali o fissi, con la quantità minima e il periodo di validità. Si
gestisce dalla vista *sconti* del modulo `4120.listini`, che ha anche le schede per collegare uno sconto ai listini
( *sconti_listini* ) e agli articoli ( *sconti_articoli* ). Il calcolo degli sconti a quantità nel carrello del modulo
`4000.catalogo` ( _mod/_4000.catalogo/_src/_lib/_mysql.utils.add.php ) è scritto ma commentato come da implementare:
oggi gli sconti si registrano e non si applicano.

colonna                          | descrizione
---------------------------------|---------------------------------------------------------------------------------------
sconti.id                        | l'ID dello sconto
sconti.id_tipologia              | l'ID della tipologia dello sconto, dalla tabella *tipologie_sconti*
sconti.nome                      | il nome dello sconto
sconti.sconto_percentuale        | lo sconto in percentuale
sconti.sconto_fisso              | lo sconto in valore assoluto
sconti.qta_min                   | la quantità minima a partire dalla quale lo sconto si applica
sconti.id_valuta                 | l'ID della valuta dello sconto fisso
sconti.timestamp_inizio          | la timestamp di inizio della validità dello sconto; NULL vuol dire senza inizio
sconti.timestamp_fine            | la timestamp di fine della validità dello sconto; NULL vuol dire senza scadenza
sconti.note                      | note sullo sconto
sconti.id_account_inserimento    | l'ID dell'account che ha inserito la riga
sconti.timestamp_inserimento     | la timestamp dell'inserimento della riga
sconti.id_account_aggiornamento  | l'ID dell'ultimo account che ha modificato la riga
sconti.timestamp_aggiornamento   | la timestamp dell'ultimo aggiornamento della riga

La tabella ha chiave primaria con AUTO_INCREMENT su *id*, l'unicità su *id_tipologia* e *nome*, gli indici su
*id_tipologia*, *nome*, *id_valuta* e sugli account.

La tabella ha le seguenti chiavi esterne:

chiave                            | campo                         | tabella e campo collegati     | comportamento
----------------------------------|-------------------------------|-------------------------------|----------------------
sconti_ibfk_01_nofollow           | id_tipologia                  | tipologie_sconti.id           | ON DELETE NO ACTION ON UPDATE CASCADE
sconti_ibfk_02                    | id_valuta                     | valute.id                     | ON DELETE SET NULL ON UPDATE SET NULL
sconti_ibfk_98_nofollow           | id_account_inserimento        | account.id                    | ON DELETE SET NULL ON UPDATE SET NULL
sconti_ibfk_99_nofollow           | id_account_aggiornamento      | account.id                    | ON DELETE SET NULL ON UPDATE SET NULL

La vista *sconti_view* relativa alla tabella *sconti* presenta le seguenti colonne:

colonna                              | descrizione
-------------------------------------|---------------------------------------------------------------------------------------
sconti_view.id                       | -
sconti_view.nome                     | -
sconti_view.timestamp_inizio         | -
sconti_view.data_ora_inizio          | la data di inizio della validità nel formato Y-m-d
sconti_view.timestamp_fine           | -
sconti_view.data_ora_fine            | la data di fine della validità nel formato Y-m-d

-------
Questa tabella *gestita* contiene la coda degli SMS in uscita.

colonna                             | descrizione
------------------------------------|---------------------------------------------------------------------------------------
sms_out.id                          | l'ID dell'SMS
sms_out.id_telefono                 | l'ID del telefono destinatario dell'SMS
sms_out.ordine                      | campo di ordinamento
sms_out.timestamp_composizione      | la timestamp di composizione dell'SMS
sms_out.mittente                    | il mittente dell'SMS
sms_out.destinatari                 | il destinatario dell'SMS
sms_out.corpo                       | il corpo dell'SMS
sms_out.server                      | il nome del server da utilizzare per l'invio dell'SMS
sms_out.host                        | il nome host del server da utilizzare per l'invio dell'SMS
sms_out.port                        | la porta del server da utilizzare per l'invio dell'SMS
sms_out.user                        | il nome utente del server da utilizzare per l'invio dell'SMS
sms_out.password                    | la password del server da utilizzare per l'invio dell'SMS
sms_out.token                       | token per il lock software della riga nelle elaborazioni automatiche
sms_out.timestamp_elaborazione      | la timestamp della marcatura con il token; il task di invio sblocca le righe marcate da più di `$cf['sms']['minuti_sblocco']` minuti, tranne quelle col token `COPIA_FALLITA` o `TROPPI_TENTATIVI`
sms_out.tentativi                   | il numero di tentativi di invio fatti per l'SMS; arrivato a `$cf['sms']['tentativi_massimi']` ( default 10 ) il task lascia la riga ferma col token `TROPPI_TENTATIVI`, e l'invio forzato dalla scheda lo azzera

sms_out.id_account_inserimento      | l'ID dell'account che ha inserito la riga
sms_out.timestamp_inserimento       | la timestamp dell'inserimento della riga
sms_out.id_account_aggiornamento    | l'ID dell'ultimo account che ha modificato la riga
sms_out.timestamp_aggiornamento     | la timestamp dell'ultimo aggiornamento della riga

La tabella deve avere le stesse colonne di *sms_sent* nello stesso ordine, perché il task di invio sposta le righe con
un `SELECT *`. Le definizioni stanno nei file di base e nella patch `_202609291000.sms.sql`, che le ha rimesse dopo
che il riallineamento del 02/03/2026 le aveva perse; *timestamp_elaborazione* l'ha aggiunta alle due tabelle la patch
`_202609301600.code.marcatura.sql`.

La tabella ha le seguenti chiavi esterne:

chiave                              | campo                         | tabella e campo collegati     | comportamento
------------------------------------|-------------------------------|-------------------------------|----------------------
sms_out_ibfk_98_nofollow            | id_account_inserimento        | account.id                    | ON DELETE SET NULL ON UPDATE SET NULL
sms_out_ibfk_99_nofollow            | id_account_aggiornamento      | account.id                    | ON DELETE SET NULL ON UPDATE SET NULL

Non c'è, e non va rimessa, la chiave verso *telefoni*: quella di prima di marzo ( `sms_out_ibfk_01_nofollow`, ON
DELETE CASCADE ) cancellava gli SMS in coda insieme al numero, e i deploy installati prima possono averla ancora.
Su *id_telefono* c'è solo l'indice.
