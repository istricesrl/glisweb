#### le patch incrementali datate

I file numerati con una data e un'ora portano ai deploy già installati quello che è cambiato nei
file di base dopo l'installazione: ai deploy esistenti i file di base non arrivano più, arrivano
solo questi. Il task /_src/_api/_task/_mysql.patch.php li legge in ordine di nome, **salta un file
intero** se il livello ricavato dal nome è minore o uguale al patch level del database, esegue ogni
blocco quando incontra il marcatore `-- |` successivo e **si ferma al primo errore**. Per questo le
patch recenti sono scritte idempotenti ( CREATE TABLE IF NOT EXISTS, ADD COLUMN IF NOT EXISTS,
INSERT IGNORE ), chiudono con `-- | FINE FILE` e mettono dentro un PREPARE guardato da
information_schema le istruzioni che su uno schema vecchio fallirebbero; ciascuna spiega nel
commento di testa perché esiste e perché ha il numero che ha.

> **attenzione** — rinumerare o correggere una patch già applicata da qualche parte richiede un
> nome con un livello più alto: con lo stesso nome il task la considera già letta e la salta.

### /_usr/_database/_patch/_202609151100.tipologie.documenti.articoli.sql
Separa la tipologia della riga di un documento da quella del documento che la contiene: nasce la tabella
tipologie_documenti_articoli ( raggruppamenti, righe che sommano, righe in alternativa ) con le sue funzioni
*_path* e la vista, documenti_articoli.id_tipologia_documento prende il contenuto della vecchia id_tipologia,
che da qui punta alla nuova tabella, e gli indici compositi di documenti_articoli si ricostruiscono. È idempotente
anche dove la migrazione era stata fatta a mano; la ricostruzione degli indici su tabelle molto grandi va messa in conto.

### /_usr/_database/_patch/_202609151300.documenti.articoli.colonne.sql
Aggiunge a documenti_articoli, con ADD COLUMN IF NOT EXISTS, tutte le colonne che documenti_articoli_view legge,
poi rifà l'unicità sul codice e la vista. Esiste perché alcuni deploy non avevano tutte le colonne dei file di base,
e la ricreazione della vista nella patch precedente falliva; il numero è 1300 e non 1200 per stare sopra al livello
a cui quei deploy si erano fermati.

### /_usr/_database/_patch/_202609151400.todo.istruzioni.sql
Porta ai deploy installati prima che entrassero nei file di base la tabella istruzioni, le colonne id_documento,
id_documenti_articoli, id_istruzione e codice di todo, la tabella taglie con taglie_view e periodicita_view;
rifà todo_view, allinea le colonne di todo_view_static e la ripopola. Il commento di testa documenta anche il
difetto dei file di base ( marcatori non crescenti, SQL dopo l'ultimo marcatore ) che aveva lasciato indietro queste patch.

### /_usr/_database/_patch/_202609151510.sedi.inline.backfill.sql
Completa la migrazione degli indirizzi inline di anagrafica_indirizzi copiando dal record indirizzi collegato i soli
campi vuoti, ed esclude le righe che collidono con l'unicità ( id_anagrafica, indirizzo ), da riconciliare a mano.
L'UPDATE è dentro un PREPARE che non fa niente dove anagrafica_indirizzi non ha ancora id_comune.

> **nota** — il file è stato rinumerato due volte: nella prima stesura non aveva marcatori `-- |` e il task lo
> leggeva senza eseguire nulla, senza errori e senza log.

### /_usr/_database/_patch/_202609171000.report.sottoscorta.sql

_mod/_0500.mastri/_src/_api/_task/_rifornimenti.da.sottoscorta.php e lette dalla scheda del sottoscorta del modulo

deduplicazione di mastri_articoli né la relativa UNIQUE.

### /_usr/_database/_patch/_202609231600.mail.status.sql
Crea tipologie_mail_status, con la scala dei verdetti Rating A+/A/B/D/F e il flag se_recapitabile, e mail_status,
