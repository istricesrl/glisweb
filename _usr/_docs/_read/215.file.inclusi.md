# i file di /_src/_inc e /_src/_html

> **nota** — capitolo travasato il 2026-09-16 dalla reference file per file che stava in
> `READ.md`, nella radice del framework. I percorsi sono stati verificati uno per uno contro
> l'albero: al travaso ne esistevano 639 su 640, e l'unico assente era un segnaposto.

I file inclusi su richiesta: le definizioni delle pagine, le macro che girano prima del rendering,
i pezzi di logica che una pagina si porta dietro, e gli snippet e le librerie di macro della linea
di template precedente a Twig puro.

#### la linea .html e la linea Twig

`/_src/_html/` e `/_src/_twig/` fanno la stessa cosa per due generazioni diverse di template, e i
file si corrispondono quasi uno a uno: `_html/_bin/_form.html` è il gemello di `_twig/_lib/_form.twig`,
`_html/_inc/_page.head.html` di `_twig/_inc/_page.head.twig`, e così via. Tutte e due le cartelle
sono sintassi Twig ( l'estensione `.html` non cambia il motore ) e tutte e due vengono aggiunte al
loader da `/_src/_api/_pages.php` con `addPath()`, prima `DIR_SRC_HTML` e poi `DIR_SRC_TWIG`, ciascuna
seguita dalla sua controparte custom. Cambia chi le usa:

- `/_src/_html/` la includono i template di `/_src/_templates/*` ( `ext/main.html` di ogni tema
  include `_inc/_page.head.html`, `_inc/_page.open.html` e `_inc/_page.close.html` ) e le maschere
  dei moduli a numero ( `_0010.anagrafica`, `_0400.documenti`, `_V300.immobiliari`, ... ), che
  importano `_bin/_form.html as frm`, `_bin/_default.html as cms`, `_bin/_navigation.html as nav` e
  `_bin/_privacy.html as prv`: sono centinaia di import, quindi la cartella è viva;
- `/_src/_twig/` la usano i template di `/_src/_tpl/*` e i moduli a lettere ( `_AN000.anagrafica`,
  `_CO000.contenuti`, `_PR000.prodotti`, ... ), che importano `_lib/*.twig`.

Le due copie non sono allineate da nessun meccanismo: una correzione fatta in un gemello va
riportata a mano nell'altro, e i commenti nel codice lo dicono spesso ( "allineato a
`_page.close.twig`" ). Gli snippet di tracciamento e di terze parti sono descritti per esteso nel
capitolo su `/_src/_twig`: qui sotto le voci di `/_src/_html/_inc/` dicono solo in cosa il gemello
`.html` si discosta.

> **attenzione** — il livello condiviso è congelato finché esiste una pagina su Bootstrap 4:
> `/_src/_html/` serve proprio i template più vecchi, quindi le classi qui dentro non si convertono.

### /_src/_html/_bin/_default.html
Libreria di macro per la rappresentazione dei contenuti, da importare come `cms` ( `{% import
'_bin/_default.html' as cms %}` ). Oltre a `picture()`, `image()`, `video()` e `formButton()`, che
corrispondono a quelle di `/_src/_twig/_lib/_default.twig`, porta macro che il gemello Twig non ha:
`videoEmbed()`, `iframeEmbed()` e `consensoMancante()` ( incorporamenti di terze parti subordinati
al consenso sui cookie, con un segnaposto al posto dell'iframe quando il consenso manca ), `audio()`
( legge `page.contents.audio`, popolato da `aggiungiAudio()` in `/_src/_lib/_mysql.utils.php` ),
slider, carousel, jumbotron, gallerie colorbox, `numeroverde()` e `shareBtn()`.

### /_src/_html/_bin/_form.html
Libreria di macro per i form compatibili con `controller()`, da importare come `frm`; è il file più
importato dell'albero ( le maschere del CMS Athena e dei moduli a numero ). Contiene i campi
( `input()`, `textarea()`, `checkbox()`, `date()`, `datetime()`, `time()` e le varianti
`*Required` / `*Disabled` ), le tendine ( `select()`, `selectPicker()`, `selectBox()` con
popolamento via API REST e attributi `restrict-*` / `sort-*` letti da `/_src/_js/_lib/_selectbox.js` ),
i pulsanti ( `button()`, `trashButton()`, `editButton()` ), `uploader()` / `shortUploader()`,
`subformLegend()`, `stars()` e `selectModalitaPagamento()` per il carrello.

> **nota** — il gemello `/_src/_twig/_lib/_form.twig` ha un insieme di macro più piccolo e firme
> diverse: una maschera non si porta da una linea all'altra cambiando solo l'import.

### /_src/_html/_bin/_navigation.html
Libreria di macro di navigazione, da importare come `nav`: `menu()`, `selectMenu()`, `lineMenu()`,
`tabs()` ( la barra delle linguette delle schede, che propaga il `__backurl__` da una linguetta
all'altra ), `sheets()`, `breadcrumbs()`, `lineBreadcrumbs()` e `flags()`. Stesse macro di
`/_src/_twig/_lib/_navigation.twig`.

### /_src/_html/_bin/_privacy.html

consensi privacy di un modulo ( contatti, registrazione, carrello ) leggendo `items.consensi`, con i
campi nascosti `__consensi__[...]` che il framework registra all'invio. Gemello di
`/_src/_twig/_lib/_privacy.twig`.

#### i controller

I file di `/_src/_inc/_controllers/` li include `controller()` in `/_src/_lib/_controller.tools.php`
durante ogni scrittura su una tabella. Il nome dice la tabella e la fase: `_<tabella>.<fase>.php`,
con gli underscore della tabella scritti come punti ( `_anagrafica.categorie.before.php` vale per
`anagrafica_categorie` ). Per ogni fase `controller()` cerca con un glob `_default.<fase>.php` e
`_<tabella>.<fase>.php`, nello standard, nei moduli attivi e nelle controparti custom, e li include
tutti con `require`: il controller vede quindi le variabili della funzione, in particolare `$t`
( tabella ), `$a` ( metodo ), `$d` ( dati ), `$ks` / `$vs` ( chiavi e valori già pronti per la
query ), `$c` ( connessione ), `$i` ( informazioni di ritorno ) e, per `PUT`, `UPDATE` e `DELETE` di
una riga esistente, `$befores` ( la riga com'era nel database prima della scrittura ). Le fasi sono
quattro:

- **before**: prima di comporre la query; può riscrivere `$ks` / `$vs`, oppure bloccare
  l'operazione mettendo uno stato di errore in `$i['__status__']` e azzerando `$a`;
- **append**: a query composta, prima dell'esecuzione;
- **after**: subito dopo l'esecuzione della query sulla riga;
- **finally**: dopo la riga principale e tutti i sotto-form, cioè a lavoro finito; è il posto per
  i ricalcoli che dipendono anche dalle righe figlie.

> **nota** — `$befores` esiste solo se la riga c'era già. Su un `POST` di una riga nuova è indefinita,
> e i controller finally che si basano solo su `$befores['id_anagrafica']` in quel caso non fanno
> niente.

### /_src/_inc/_controllers/_anagrafica.categorie.before.php
Controller before della tabella `anagrafica_categorie`: in scrittura, se arriva `codice_anagrafica`
invece di `id_anagrafica`, lo converte cercando l'id in `anagrafica` e toglie il codice dai campi. In
quel caso copia anche `id_anagrafica` e `id_categoria` in `$befores`, perché il finally li ritrovi
anche su una riga nuova ( un commento nel codice ammette che il meccanismo "funziona a metà" ).

### /_src/_inc/_controllers/_anagrafica.categorie.finally.php
Controller finally di `anagrafica_categorie`: dopo ogni scrittura o cancellazione ricava l'anagrafica
toccata ( da `$befores`, dal codice, da `$d` o da `$vs`, in quest'ordine ) e chiama
`updateAnagraficaViewStatic()` per rigenerarne la riga nelle view statiche. La funzione la definisce
il modulo anagrafica attivo ( `_0010.anagrafica` o `_AN000.anagrafica` ).

### /_src/_inc/_controllers/_anagrafica.indirizzi.before.php
Controller before di `anagrafica_indirizzi`: converte `codice_anagrafica` in `id_anagrafica`, come
gli altri before di questa cartella.

### /_src/_inc/_controllers/_anagrafica.indirizzi.finally.php
Controller finally di `anagrafica_indirizzi`: se `$befores['id_anagrafica']` è valorizzato chiama
`updateAnagraficaViewStaticIndirizzi()` per aggiornare gli indirizzi nella view statica
dell'anagrafica. Su un inserimento nuovo `$befores` non c'è e l'aggiornamento non parte.

### /_src/_inc/_controllers/_default.after.php
Questa controller viene eseguita dopo ogni ciclo di lavoro della funzione controller().

### /_src/_inc/_controllers/_default.append.php
Questa controller viene eseguita durante ogni ciclo di lavoro della funzione controller(), dopo la composizione della query e prima della sua esecuzione.

### /_src/_inc/_controllers/_default.before.php
Questa controller viene eseguita prima di ogni ciclo di lavoro della funzione controller().

### /_src/_inc/_controllers/_default.finally.php
Questa controller viene eseguita dopo ogni gruppo di cicli di lavoro della funzione controller(), cioè dopo il ciclo principale e dopo tutti i sotto cicli
per i subform.

### /_src/_inc/_controllers/_file.before.php
Controller before della tabella `file`, con due compiti. Su `DELETE`, se il file è un allegato di una
mail in coda ( `file.id_mail_out` ), riscrive `mail_out.allegati` con i percorsi degli altri allegati,
così la mail non parte con un file che non c'è più. Su `POST` e `UPDATE` rifiuta una riga senza
`path`: mette `$i['__status__']` a 422 e azzera `$a`, e l'operazione non viene eseguita. La riga di
log dice "finally" ma il file è un before.

### /_src/_inc/_controllers/_indirizzi.finally.php
Controller finally della tabella `indirizzi`: dopo ogni scrittura chiama `sincronizzaIndirizzoInline()`
( `/_src/_lib/_mysql.utils.php` ), che ricopia l'indirizzo per esteso in tutte le righe di
`anagrafica_indirizzi` che lo citano. Serve perché il form dell'anagrafica scrive su `indirizzi`,
mentre documenti e stampe leggono la copia inline in `anagrafica_indirizzi`: senza questo passaggio
un documento emesso dopo una correzione stamperebbe l'indirizzo vecchio.

### /_src/_inc/_controllers/_mail.before.php
Controller before della tabella `mail`: converte `codice_anagrafica` in `id_anagrafica`.

### /_src/_inc/_controllers/_mail.finally.php
Controller finally della tabella `mail`: se `$befores['id_anagrafica']` è valorizzato chiama
`updateAnagraficaViewStaticMail()` per aggiornare le mail nella view statica dell'anagrafica. Come
per gli indirizzi, su una riga nuova l'aggiornamento non parte.

### /_src/_inc/_controllers/_telefoni.before.php

### /_src/_inc/_controllers/_telefoni.finally.php

### /_src/_inc/_controllers/_url.before.php
Controller before della tabella `url`: converte `codice_anagrafica` in `id_anagrafica` e, se il campo

#### le macro di default: due copie

Le macro di default esistono in due copie. Quelle direttamente in `/_src/_inc/_macro/` le includono
le macro dei moduli a numero ( `_0010.anagrafica`, `_0400.documenti`, `_V300.immobiliari`, ... ) con
`require DIR_SRC_INC_MACRO . '_default.form.php'`; quelle in `/_src/_inc/_macro/_default/` le
includono i moduli a lettere e le macro del core ( `_dashboard.php`, `_strumenti.php` ). Le due copie
sono divergenti e vanno corrette separatamente.

### /_src/_inc/_macro/_default.form.multilingua.php
Per i form con sotto-form `contenuti`, aggiunge a `$_REQUEST` una riga vuota per ogni lingua che non
ha ancora un contenuto, così il form mostra un blocco per ciascuna lingua. Cicla su
`$cf['localization']['languages']`, mentre la copia in `_default/` cicla su `$ct['tr']['languages']`.
La includono le macro `*.form.testo.php` e `*.form.sem.php` dei moduli a numero.

### /_src/_inc/_macro/_default.form.php
Logica comune alle pagine di tipo form dei moduli a numero: imposta `action`, `method` ( `post` o
`update` ) e `activity` del form, mette la `__label__` dell'oggetto nel titolo, calcola e registra i
backurl ( quello verso la prima linguetta della scheda, quello di ritorno della pagina, quello
dell'ultima briciola ) con `backurlRegistra()`, stabilisce `page.__sottooggetto__` che i template
usano per scegliere fra dischetti e pallini, e prepara i sotto-form dei metadati da
`$ct['etc']['metadati']`.

### /_src/_inc/_macro/_default.stats.php
Macro di appoggio per le pagine statistiche: prepara le tendine `confronti` e `precisioni` e, dati
`__stats__[__inizio__]`, `__fine__` e `__precisione__`, costruisce le etichette dell'asse temporale e
la serie `corrente` azzerata per il grafico. La usano solo `_anagrafica.stats.php` e
`_anagrafica.form.stats.php` di `_0010.anagrafica`. Usa `strftime()`, deprecata da PHP 8.1.

### /_src/_inc/_macro/_default.tools.php
Per le pagine a metro: raccoglie i modal dichiarati dai metro ( `metro.modal.include` ) in
`$ct['page']['contents']['modals']['metro']`, perché il template li includa. La includono le macro
`*.tools.php` e `*.stampe.php` dei moduli a numero; stesso codice della copia in `_default/`.

### /_src/_inc/_macro/_default.view.php
Logica comune alle pagine di tipo view dei moduli a numero: calcola id e backurl della vista, unisce
filtri, ordinamenti, paginazione e modalità presettati con quelli della richiesta, preleva i dati con
`controller()`, stabilisce le pagine di gestione e di inserimento, calcola il colspan della riga di
totale e converte le date in formato GG/MM/AAAA. La chiave di configurazione della vista è
documentata nel docblock della copia in `_default/`.

### /_src/_inc/_macro/_default/_default.form.php
Questa macro contiene le logiche comuni a tutte le pagine di tipo form.

### /_src/_inc/_macro/_default/_default.form.multilingua.php
Questa macro contiene le logiche necessarie al funzionamento dei form multilingua.

### /_src/_inc/_macro/_default/_default.tools.php
Questo file è una macro di default inclusa soprattutto da pagine che utilizzano lo schema metro.

### /_src/_inc/_macro/_default/_default.view.php
Questa macro contiene le logiche comuni a tutte le pagine di tipo view.

### /_src/_inc/_macro/_delete.php
Questa è la macro della pagina di cancellazione del template Athena e si occupa fra le altre cose di chiedere la conferma all'utente prima della cancellazione.

### /_src/_inc/_macro/_mail.tools.php
Macro della pagina "strumenti mail": aggiunge i metro per svuotare le code `mail_sent` e `mail_out`

> **attenzione** — nessuna pagina punta a questo file. `_MA000.mail` usa la propria copia,

### /_src/_inc/_macro/_security.php
Questo file implementa il firewall applicativo del framework ed è quindi cruciale per la sua sicurezza. Viene incluso da /_src/_config.php e si occupa
di filtrare le richieste potenzialmente dannose. Per i dettagli del suo funzionamento si vedano i commenti al codice.

### /_src/_inc/_macro/_strumenti.php
Questa è la macro della pagina strumenti del template Athena.

### /_src/_inc/_macro/_user.php
Macro vuota ( solo un docblock ) della pagina `user` dichiarata in `_user.it-IT.php`: è un aggancio
da personalizzare con una controparte custom.

### /_src/_inc/_pages/_app.en-GB.php
Questo file contiene la dichiarazione delle pagine della web app standard del framework in inglese.

### /_src/_inc/_pages/_app.it-IT.php
Questo file contiene la dichiarazione delle pagine della web app standard del framework in italiano.

### /_src/_inc/_pages/_dashboard.it-IT.php
Questo file contiene la dichiarazione delle pagine della dashboard del CMS.

### /_src/_inc/_pages/_delete.it-IT.php
Questo file contiene la dichiarazione della pagina di cancellazione del CMS.

### /_src/_inc/_pages/_legal.en-GB.php
Questo file contiene la dichiarazione delle pagine legali in inglese.

### /_src/_inc/_pages/_legal.fr-FR.php
Questo file contiene la dichiarazione delle pagine legali in francese.

### /_src/_inc/_pages/_legal.it-IT.php
Questo file contiene la dichiarazione delle pagine legali.

### /_src/_inc/_pages/_null.en-GB.php
Versione inglese della pagina `NULL`, quella servita con stato HTTP 404 quando l'indirizzo non
corrisponde a nessuna pagina: titolo, h1 e testo in inglese, template `_src/_tpl/_aurora/`. Come
tutti i file di pagine viene caricato solo se la lingua `en-GB` è attiva, e le sue chiavi si fondono
con quelle di `_null.it-IT.php`.

### /_src/_inc/_pages/_null.it-IT.php
Questo file contiene la dichiarazione della pagina NULL utilizzata per l'errore HTTP 404.

### /_src/_inc/_pages/_password.en-GB.php
Versione inglese delle pagine `password.reset` e `password.reinsert`, con la macro
`_password.reset.php`. Punta ancora ai template della vecchia linea ( `_src/_templates/_athena/` e
`_src/_templates/_lydia/`, schema `password.reset.html` ), mentre `_password.it-IT.php` punta a
`_src/_tpl/`: con entrambe le lingue attive le chiavi si fondono e vince il template dichiarato
dall'italiano, che viene caricato dopo.

### /_src/_inc/_pages/_password.it-IT.php
Questo file contiene la dichiarazione delle pagine per il reset della password.

### /_src/_inc/_pages/_site.it-IT.php
Questo file è vuoto in modo che possa essere facilmente customizzato.

### /_src/_inc/_pages/_strumenti.it-IT.php
Questo file contiene la dichiarazione delle pagine strumenti del CMS.

### /_src/_inc/_pages/_user.it-IT.php
Dichiara la pagina `user` ( "area utente" ), con la macro vuota `_user.php` e un'icona nel menu
`icons`. Il template dichiarato è `_src/_templates/_lydia/`, schema `user.html`, che nell'albero non
esiste ( c'è solo `/_src/_tpl/_lydia/user.twig` ): così com'è la pagina non ha un template da
rendere, e va ridefinita da un file custom.
