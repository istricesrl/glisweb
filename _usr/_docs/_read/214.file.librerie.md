# i file di /_src/_lib

Le librerie di funzioni, caricate per intero a ogni richiesta. Il nome dice il tipo: `tools` sono
utility che stanno in piedi da sole, `utils` dipendono da `$cf` e `$ct`.

### /_src/_lib/_acl.utils.php
Questa libreria contiene le funzioni di utilità per la gestione dei permessi degli utenti.

### /_src/_lib/_analytics.tools.php
Invio di eventi a Google Analytics lato server, tramite il Measurement Protocol di GA4
( `https://www.google-analytics.com/mp/collect` ) e `restCall()`. Le funzioni vive sono `ga4event()`, che spedisce un
evento qualsiasi, e `ga4purchase()`, che compone l'evento `purchase` da un carrello concluso e che il modulo e-commerce
chiama in `_checkout.finally.success.php` con `$cf['google']['profile']['analytics']['ua']` e
`['mp']['secret']`. Le funzioni `analytics*Hit()` e `analyticsPurchase()` parlavano a Universal Analytics, che Google ha
dismesso, e nessuno le chiama più.

### /_src/_lib/_apcu.tools.php
Questa libreria contiene le funzioni per l'utilizzo della cache APCU.

### /_src/_lib/_archivium.utils.php
Client delle API REST di Archivium, il servizio usato per la fatturazione elettronica verso lo SdI: censimento
dell'azienda ( `archiviumPostInsertAzienda()` ), invio delle fatture attive ( `archiviumPostInvioFeAttiva()` ), scarico e
registrazione delle fatture passive e delle note ( `archiviumGetListaFePassive()`, `archiviumRegistraFePassiva()`,
`archiviumGetListaNoteAttive()`, `archiviumRegistraNotaAttiva()` ). La chiamano i task e i job di `_mod/_0400.documenti`
e `_src/_api/_task/_anagrafica.attivazione.archivium.php`. Legge `$cf['archivium']['profile']` ( `url`, `id`, `apikey`,
runlevel 560/565 ) e scrive nel database tramite `$cf['mysql']['connection']`: per questo è `utils`.

### /_src/_lib/_array.tools.php
Questa libreria contiene una collezione di funzioni per la manipolazione degli array.

### /_src/_lib/_controller.tools.php
Questa libreria contiene la funzione controller() e le sue funzioni di appoggio.

### /_src/_lib/_cron.utils.php
Calcolo delle date di una ripetizione nel tempo. Il cuore è `creazionePianificazione()`, che data una data di partenza,
una periodicità ( id della tabella `periodicita` ), una cadenza e un limite restituisce l'elenco delle date: la usano
i task di popolamento delle pianificazioni ( `_mod/_0100.pianificazioni`, `_mod/_PI000.pianificazioni` ) e
`_src/_api/_task/_creazione.pianificazione.php`. `pianificazioneTodo()` crea una todo per ciascuna di quelle date
( `_src/_api/_task/_todo.generazione.php` ); `createDateRangeArray()` e `daysBetweenDates()` servono ai job dei corsi
e delle todo. Non legge `$cf`: il nome `utils` è una svista che il commento in testa al file già segnala.

### /_src/_lib/_cryptography.tools.php
Questa libreria contiene alcuni strumenti per la gestione della crittografia.

### /_src/_lib/_csv.tools.php
Questa libreria contiene una collezione di strumenti per la manipolazione dei file e dei dati in formato CSV.

### /_src/_lib/_docs.tools.php
Le funzioni che trasformano i sorgenti markdown della documentazione ( `READ.md`, `USER.md`, i capitoli, le
quickstart ) nelle pagine HTML statiche: `docsParseSections()` e `docsFilterSections()` spezzano e filtrano per
metadati, `docsMarkdown2Html()` converte, `docsRenderCallouts()` e `docsAnchorHeadings()` rifiniscono,
`docsRenderPage()` impagina. Definisce i vocabolari chiusi dei marcatori ( `DOCS_META_VOCABOLARIO`,
`DOCS_CALLOUT_VOCABOLARIO`, ... ). La chiama solo `_src/_cli/_docs.build.php`, non legge `$cf` e dipende da
`league/commonmark` ( Composer ): senza la libreria `docsMarkdown2Html()` restituisce `false`.

### /_src/_lib/_ehiweb.tools.php
Invio di un SMS tramite il gateway HTTP di Ehiweb ( `https://secure.apisms.it/http/send_sms` ) con la sola
`ehiwebSend()`, che accetta anche un array di destinatari e li spedisce uno per uno. Credenziali, mittente e
`id_api` arrivano come parametri: li passa `_src/_api/_task/_sms.queue.send.php` prendendoli dal server SMS in
`$cf['sms']['servers']` quando il suo `type` è `ehiweb`.

### /_src/_lib/_emailable.utils.php
Verifica della recapitabilità degli indirizzi mail tramite le API di Emailable, sia uno per volta
( `emailableVerifyOne()`, chiamata da `_src/_api/_emailable.verifica.php` sul blur dei campi mail dei form ) sia in
blocco ( `emailableVerifyStart()` ed `emailableVerifyResult()`, per ora senza chiamanti nell'albero ). I verdetti
stanno in cache nella tabella `mail_status` ( `mailStatusRead()`, `mailStatusWrite()` ). Legge
`$cf['emailable']['profile']` ( `apikey`, `apikey_server`, `ttl`, runlevel 600/605 ) e lavora in *fail-open*: se il
servizio non risponde l'indirizzo passa, e si boccia solo uno stato `undeliverable`.

### /_src/_lib/_facebook.tools.php
Integrazione con Meta: la Conversions API per gli eventi di conversione lato server e la Graph API per le pagine.
L'unica funzione implementata e usata è `fbEventAddToCart()`, che il controller di `_mod/_4170.ecommerce` chiama
con `$cf['facebook']['profile']` ( `pixel/id` e `pixel/token`, runlevel 640/645 ) quando un articolo entra nel
carrello; `fbPurchase()`, `fbLead()` e gli altri eventi sono segnaposto vuoti, e `getFbPageAccessToken()` e
`getFbPageReviews()` non hanno chiamanti. Tutte le chiamate passano da `restCall()` verso `graph.facebook.com`.

### /_src/_lib/_filesystem.tools.php
Questa libreria contiene una collezione di funzioni per la gestione dell'I/O sul filesystem.

### /_src/_lib/_filesystem.utils.php
Contiene la sola `path2url()`, che trasforma il percorso di un file in URL pubblico sul sito indicato, con il ramo
`/mailing/<id>` per gli allegati delle mailing; converte in UTF-8 i nomi con un'altra codifica e scrive gli errori nel
log `details/localization`. È `utils` perché legge `$cf['sites'][ $s ]['url']`. La usano `_src/_lib/_mail.tools.php` e
il task `_genera.mail.php` di `_mod/_7000.mailing`.

### /_src/_lib/_geocode.tools.php
Calcoli sulle coordinate geografiche, senza servizi esterni: `getCoordsDistance()` ( distanza in chilometri fra due
punti, usata da `_mod/_1000.produzione` ), la conversione fra gradi sessagesimali e decimali ( `degrees2coords()`,
`coords2degrees()`, `string2coords()` ) e la scomposizione di un indirizzo in via e civico ( `splitAddress()` ). Non
legge `$cf`; per ottenere le coordinate di un indirizzo si usa `_src/_lib/_mapquest.tools.php`.

### /_src/_lib/_google.tools.php
Libreria abbozzata per le API di Google. `googleGetAccessToken()` ha il corpo commentato e si limita a un
`print_r()`; `yt_api_get()` è un `GET` con cURL e timeout che restituisce codice, corpo ed errore. Il docblock conserva
la procedura manuale per ottenere un refresh token OAuth. Nessun file del framework o dei moduli la chiama.

### /_src/_lib/_job.utils.php
Dove tenere il dataset di un job in background fra un'iterazione e l'altra. `jobDatasetScrivi()` prova memcache
( `$cf['memcache']['connection']` ) e, se la cache rifiuta il dato perché troppo grande, ripiega su un file serializzato
in `var/spool/job/<id>.dataset`, restituendo l'esito perché finisca nel workspace del job; `jobDatasetLeggi()` e
`jobDatasetPulisci()` lo rileggono e lo cancellano. La usano le importazioni di anagrafiche
( `_src/_api/_job/_anagrafica.importazione.php` ) e di articoli dei documenti.

### /_src/_lib/_json.tools.php
Due funzioni sottili sopra `json_decode()`: `jsonCheck()` dice se una stringa è JSON valido, `jsonValidate()` la
decodifica e scrive nel log il tipo di errore. Non legge `$cf`, non ha dipendenze e oggi nessun file del framework o
dei moduli la chiama.

Invio di un messaggio di log a Google Cloud Logging con `log2google()`, accanto ai log su file di `logger()` e

libreria Composer `google/cloud-logging`, che non è fra quelle installate dal `composer.json` del framework: se manca
la funzione scrive l'errore e restituisce `false`. Nessuna parte del framework la chiama.

la chiave `$cf['mapquest']['server']['key']` ( runlevel 520/525 ), e ogni risposta finisce in un file sotto

### /_src/_lib/_monetaweb.tools.php
Avvio di un pagamento MonetaWeb ( Nexi, protocollo XML ): `monetawebGetPaymentDetails()` chiede al gateway un
`paymentid` e l'URL della pagina di pagamento ospitata e restituisce `redirecturl`, a cui il riepilogo del carrello

#### le librerie Python di /_src/_py/_lib

Le librerie di `_src/_py/_lib/` servono a un solo strumento, `_src/_py/_mysql.populate.py`, che popola il database
di un deploy con dati casuali verosimili per le demo e i collaudi ( anagrafiche, catalogo, documenti, progetti,
notizie, mailing ). Si lanciano quindi sempre attraverso di lui, dalla document root, per esempio
`_src/_py/_mysql.populate.py --elenco` o `_src/_py/_mysql.populate.py anagrafica --quantita 200 --secco`. Il nome segue
la convenzione del framework ( `tools` stanno in piedi da sole, `utils` dipendono dal contesto ) e non è un nome di
modulo Python valido: lo script le carica a mano e le registra come `_casuali_tools`, `_mysql_tools` e così via,
senza scrivere `__pycache__`. Non richiedono pacchetti esterni: niente driver MySQL e niente PyYAML.

### /_src/_py/_lib/_casuali.tools.py
Generatori di valori casuali ma coerenti: la classe `Casuali` produce nomi, denominazioni, date di nascita,
recapiti, indirizzi e testi, e le funzioni `calcola_codice_fiscale()`, `calcola_cin()` e `calcola_controllo_iban()`
fanno sì che codice fiscale, IBAN e partita IVA superino le validazioni delle interfacce. Non legge configurazione né
database.

### /_src/_py/_lib/_catalogo.tools.py
La classificazione delle tabelle in standard, assistite e gestite, allineata a `_usr/_docs/_read/300.database.md`:
`classifica()`, `scrivibile()` e `verifica_scrivibili()` decidono dove lo strumento può scrivere ( solo nelle
gestite ), `leggibile_per_lookup()` da dove può pescare valori, `vista_statica()` dà il nome della vista materializzata
di una tabella. Una tabella che non compare in nessuna lista è trattata come non scrivibile.

### /_src/_py/_lib/_config.tools.py
Legge la configurazione del deploy replicando l'ordine del bootstrap di `_src/_config.php` ( YAML poi JSON, `ext/` poi
`src/`, `config.*` poi `shadow.*` ) con `carica()`, e con `parametri_mysql()` ne estrae il server MySQL del profilo
richiesto ( `mysql/profiles/<DEV|TEST|PROD>/servers` e `mysql/servers` ). Per i file YAML chiede a PHP
( `yaml_parse()` ) invece di dipendere da PyYAML, e se non ci riesce lo dice.

### /_src/_py/_lib/_mysql.tools.py
Client MySQL minimale sopra il comando `mysql`, perché sulle macchine del framework non c'è un driver Python: la classe
`Mysql` offre `seleziona()`, `valore()` ed `esegui_script()`, e le funzioni `virgoletta()` e `inserimento()`
compongono l'SQL. La password non passa mai dalla riga di comando: va in un file temporaneo con permessi 600 letto con
`--defaults-extra-file`.

### /_src/_py/_lib/_ricette.utils.py
Le ricette di popolamento, una per entità: `genera_anagrafica()`, `genera_catalogo()`, `genera_documenti()`,
`genera_progetti()`, `genera_notizie()` e `genera_mailing()` costruiscono in memoria la riga principale con il suo
corredo, classificato come obbligatorio, consigliato o opzionale ( le opzioni `--con`, `--senza` e `--forza` dello
script ). È `utils` perché la classe `Contesto` legge dal database del deploy le tipologie, le categorie e i ruoli
esistenti.

### /_src/_py/_lib/_schema.tools.py
Introspezione di `information_schema` con la classe `Schema`: sapere quali colonne esistono davvero ( `filtra()` ),
assegnare gli id in memoria ( `prossimo_id()` ) per scrivere tutto in una transazione, ordinare gli inserimenti lungo
le chiavi esterne e pianificare lo svuotamento ( `piano_svuotamento()` ) e il rifacimento delle viste statiche
( `piano_viste_statiche()` ). Lo svuotamento è un `DELETE` mirato, non un `TRUNCATE`, e risparmia le righe a cui sono
agganciate tabelle protette come `account`.
