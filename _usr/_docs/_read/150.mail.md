Descrizione della factory mail del framework.

introduzione
============
La factory mail è la parte del framework che si occupa della creazione e dell'invio delle mail.

code delle mail in uscita e inviate
===================================
Le mail si accodano nella tabella `mail_out` con `queueMail()` o `queueMailFromTemplate()` di
`_src/_lib/_mail.tools.php`; il task `_src/_api/_task/_mail.queue.send.php` ( o la sua copia nel modulo `MA000.mail` )
ne invia una per giro con `sendMail()` e la sposta nell'archivio `mail_sent`, che ha le stesse colonne nello stesso
ordine. Una mail che non parte resta in coda e viene riprovata dopo tante ore quanti sono i tentativi fatti; una mail
partita ma non copiata fra le inviate resta in `mail_out` bloccata dal token del giro, con un errore critico nel log
`mail`, e va sistemata a mano. Dalla scheda di una mail inviata il task `mail.queue.resend` del modulo `MA000.mail` la
rimette in coda con tentativi e data prevista azzerati. I dettagli stanno nelle voci dei task in `212.file.api.md` e
nel `READ.md` del modulo.

template per le mail
====================

la funzione queueMailFromTemplate()
-----------------------------------
```php
// accodamento
    queueMailFromTemplate(
        $cf['mysql']['connection'],
        $cf['mail']['tpl']['DEFAULT'],
        array( 'dt' => array( 'chiave' => 'valore' ), 'ct' => $ct ),
        strtotime( '+5 minutes' ),
        array( 'Pinco Pallo' => 'pinco.pallo@domain.bogus' ),
        'it-IT'
    );
```

### come abilito la firma DKIM per la posta inviata dal framework?
Le chiavi DKIM vengono memorizzate in /etc/secret/<nomeDominio>; per utilizzarle è necessario aggiungere un record DKIM al proprio DNS. Lo script
/_src/_sh/_dkim.keygen.sh è pensato per aiutare in questo processo.
